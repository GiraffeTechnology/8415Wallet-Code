# Source-managed authentication code upgrades

The ordinary installer receipt is not interchangeable with a prepared source installation receipt. `prepare` refuses an existing instance; ordinary `upgrade` retains its strict installer inspection. Never edit a historical receipt to bypass that boundary.

`deploy/auth-runtime/source-mode-upgrade.mjs` provides pure metadata planning and post-drain receipt preparation for the existing **uninitialized, auth-only** source-managed case. It performs no file reads, writes, service calls, credential loading or state initialization. An operator must verify externally pinned current receipt, running code/unit/startup identity, candidate release, original configuration reference and runtime state contract. Retained historical witness validation does not establish a fresh drain.

`planSourceModeUpgrade` returns a source- and reference-bound immutable plan, explicitly requiring fresh drain evidence. `finalizeSourceModeUpgrade` requires the same plan digest, an exclusive operator lock, a completed graceful drain of that exact prior process, held writer-lock provenance and fresh directory observations, absent state and writer lock after drain, unchanged configuration/unit/code/current references and monotonic event ordering. It derives a new candidate-bound witness from those observations while retaining previous receipt/witness provenance. It does not copy old witness source fields or activate code. The operator must apply only the reviewed plan under the still-held lock, record real outcomes and preserve the old release; an unknown start never licenses state rollback or replay.

An existing encrypted state or a change of state generation/authorization semantics is explicitly refused by this narrow adapter. Such cases need a separate verified forward-compatibility path covering original grants, scope, expiry, revocations, owner settings, UNKNOWN operations and origin continuation. Merely avoiding explicit store writes does not prove compatibility. No new identity, wallet binding, credential or business authority follows from this module.

Configuration references include device, inode, size, ctime, mtime, owner, permissions and link identity without reading secret content. The post-drain record must retain all of them, and must independently remeasure the Node binary identity/hash, unit/drop-in digest, entry and store-source hashes. These functions only validate supplied, trusted operator observations. They cannot prove that measurements were taken or a lock is still held; the real privileged apply path must recheck under the same lock immediately before applying the receipt and switch, and must not treat a generated plan/receipt as activation evidence.

## Immutable payload and private receipt layout

For a packaged release, the runtime remains `<instance>/releases/<tree>/` with the exact AUTH-RELEASE inventory. Its private receipt is `<instance>/source-installations/<tree>.json`, outside that inventory, under a root-owned 0700 directory and as a root-owned 0600 regular file. The entry derives this path from its real canonical working directory, without a caller path, environment override or changed unit arguments. It binds receipt source commit/tree/runtime to the release and requires the explicit `external-instance-metadata/1` capability. Missing external metadata is a hard failure, never fallback to a receipt inside the package. An in-payload private receipt is refused. Legacy nonpackaged source installations retain their original protected receipt location.

The apply operator must verify the entire packaged runtime with the unchanged auth verifier both before and after preparing the separate metadata, and independently verify the private metadata pin/ownership. No extra payload file, manifest rewrite or broad verification exception is permitted. The original packaged release without this entry capability cannot use this layout; an updated reviewed source/build is required. The current unit working directory, parameters, identity, credential delivery, configuration, state and socket references remain unchanged.
